# 配电检修安全票协同系统

调度员在拓扑快照上圈定工作区，系统自动推导安全边界（必须断开的开关、接地线、禁止操作范围）；
现场人员逐项回报设备位置并由第二人复核，全部隔离条件满足后调度员才能许可开工；检修期间持续校验
安全边界，收工送电严格按依赖逆序执行。全过程保证设备控制权唯一、审计顺序完整。

## 运行

```bash
pip install fastapi uvicorn pytest httpx
python3 server.py          # http://localhost:8000
```

- 调度端拓扑视图： http://localhost:8000/
- 现场操作页面：   http://localhost:8000/field
- 工器具借还台：   http://localhost:8000/tools
- 计量检定与召回： http://localhost:8000/metro
- 换班接续台：     http://localhost:8000/shift
- 审计事件回放：   http://localhost:8000/replay
- 事故分析报告：   http://localhost:8000/report
- 外发凭证柜：     http://localhost:8000/voucher
- 雷暴撤离调度端： http://localhost:8000/storm
- 雷暴撤离移动端： http://localhost:8000/storm-mobile
- 接口文档（Swagger）：http://localhost:8000/docs

## 现场班组工器具借还台

调度员从安全票的隔离/恢复步骤推导**必需工具清单**（`GET /api/tools/requirements/{tid}`，
断开关→绝缘手套/验电器/绝缘操作杆，装接地→绝缘手套/接地棒，按步骤数汇总），
库管员按**批次**把具体单件锁给安全票（`POST /api/tickets/{tid}/tool-locks`），
现场人员用扫码器逐件领用（`POST /api/tool-boxes/{bid}/scan`）。

- **批次锁定整批原子**：任一工具编号重复（已被他票锁定/领用）、维修中或库存不足，
  整批锁定全部回滚，不留下半成品锁；占用场景返回具体占用票据（`ITEM_OCCUPIED_BY_TICKET`）。
- **逐件扫码与可复核校验串**：服务端对每件已领工具按
  `HMAC-SHA256(密钥, 箱|票|型号|批次|编号)` 生成 `tlc.<20位>` 校验串（密钥持久化，
  重启后复核一致，`GET /api/tool-boxes/{bid}/verify/{serial}`）；
  重复扫码（任意扫码器）返回**首次原结果**（`DUPLICATE_SCAN`）；
  未按本票批次锁定（`NOT_LOCKED_FOR_TICKET`）、批次/编号不符（`BATCH_MISMATCH`）、
  已被另一张安全票占用（`ITEM_OCCUPIED_BY_TICKET`）都给出具体原因且不扣库存。
- **齐套才能移交**：缺件（`BOX_NOT_COMPLETE`）、封签破损（`SEAL_BROKEN`，箱扣留
  `BLOCKED`）、超过交接期限（`HANDOVER_DEADLINE_PASSED`）均拒绝并在 `tool_reasons` 留可查原因；
  两个负责人并发争抢同一箱，以条件更新 CAS（`holder IS NULL`）保证**只有一人拿到持有权**，
  负方收到带中签者的确定失败原因。
- **断网本地队列补送**（`POST /api/tool-scans/flush`）：扫码动作按
  `(client_id, client_seq)` 客户端位置定序；缺前置动作的后续内容先 `PENDING` 挂起，
  前序补到后**链式唤醒**；重复补送返回首次原结果，**绝不多扣库存**（失败裁决也占位置但不阻塞后续）。
- **归还清点**（`POST /api/tool-boxes/{bid}/return`）：归还数量、工具磨损、单件/箱封签
  与领用清单逐项对照；缺件/多还串箱/磨损/封签变化任一差异即把工具箱置为**待复核 REVIEW，
  禁止再次借出**；库管员可复核结案（`CONFIRM_LOSS` 仅缺损件转维修、好件回库；`CLEAR` 全部回库）。
- **库存回滚**：撤回安全票时未出箱的批次锁整批释放（`TOOLS_LOCK_ROLLBACK`）；
  未齐套箱可由库管员作废回滚（`POST /api/tool-boxes/{bid}/abort`，已持有箱必须走归还）；
  维修/更换完成的单件可回库（`POST /api/tools/repair/{serial}`）。
- **重启恢复**：工具/批次/库存锁/工具箱/领用校验串/补送游标/挂起事件/处理原因全部
  事务化持久化于 SQLite，`POST /api/admin/reopen` 后挂起队列可继续补送、校验串复核一致。
- 借还台页面（`/tools`）展示**安全票、工具箱、库存锁、校验串、持有人和每条处理原因**，
  可一键演示八幕：齐套领用、重复扫码、并发抢占、断网补送、损坏差异、库存回滚、
  异常扫码（他票占用/未锁定/封签破损/超期）、服务重启后继续处理。

## 计量工器具检定与批次召回

检定员为验电器（VDT）、力矩扳手（WRENCH）等计量器具登记**带生效区间与适用电压等级的证书版本**
（`POST /api/metro/certificates`）；调度侧创建安全票时携带**计划作业时段与电压等级**，
库管锁定/扫码准备清单时逐件校验资格。

- **证书版本化、一经使用即固化**：同一器具逐版追加（`metro_certs.ver`），登记后继版本时旧
  ACTIVE 行置 `SUPERSEDED` 但内容原样保留；证书一旦用于现场任务（锁定纳入准备清单即 `used=1`，
  领用行 `checkouts.cert_id/cert_ver` 再固化一次）即拒绝任何覆盖修改（`CERT_IN_USE_IMMUTABLE`），
  只能形成后继版本；未使用证书允许笔误更正（`force_amend`）。证书可暂停/恢复，重复操作幂等。
- **准备清单按计划时段+电压校验**：证书**将在作业结束前到期**（`CERT_EXPIRES_BEFORE_JOB_END`）、
  被暂停（`CERT_SUSPENDED`）、已被后继版本取代（`CERT_SUPERSEDED`）、作业开始后才生效、
  **不适用于当前电压等级**（`CERT_NOT_APPLICABLE_VOLTAGE`）、无证或器具正被召回（隔离/冻结/撤资格），
  均不得纳入准备清单；整批锁定原子回滚并返回逐件可核对原因码；自动选件只挑合格件。
  资格预览见 `GET /api/tickets/{tid}/tool-eligibility`。
- **锁后变化的现场闸门**：锁行固化当时证书版本；锁后证书被暂停/换版/到期或器具被召回，
  逐件扫码（在线/断网补送同一路径）在现场闸门按持久化版本拒绝（可核对原因），
  已领用件的重复扫码永远返回首次原结果，绝不改写当时使用的证书。

质量负责人可按**器具编号、生产批号或证书版本**发起召回（`POST /api/metro/recalls`，
证书版本范围形如 `C-VDT-B2311-01@1`）。一个事务给出受影响清单并按**当时状态**处置：

- **库内器具 → 隔离**（`tools.state=QUARANTINED`），不能再锁定/出场/维修回库；
- **已预留未出库 → 撤销资格**（锁行 `metro_state=DISQUALIFIED` 保留可查、不计齐套，
  建箱被拒 `LOCK_REVOKED_BY_RECALL`，需另补合规格器具），实物转隔离；
- **现场正在使用 → 保留真实持有记录**（`checkouts` 原样、仍为 ISSUED）但 `metro_frozen=1`，
  后续许可在现场闸门一律停止（`ITEM_RECALL_FROZEN`），冻结原因持久化在 `tools.freeze_reason`；
- **已归档历史 → 只追加召回标记**（`metro_marks.ARCHIVE_MARK`），绝不改写归档领用当时使用的证书。

- **并发唯一裁决与幂等**：召回与证书换版、任务许可并发时，全部以持久化版本（DB 行状态 +
  `db.lock` 串行化 + 唯一索引）决定唯一结果；召回以“范围+原因”自然键及可选幂等键去重，
  **相同召回再次提交返回原结果**，不重复冻结、不重复撤销、不追加两条相同审计/标记
  （`UNIQUE(recall,serial,kind,ref_type,ref_id)` 兜底）。
- **复检解除、部分恢复**（`/rechecks`、`/release`）：解除必须引用一次 PASS 复检结论；
  只恢复“通过复检**且没有被其他有效召回覆盖**”的器具（被覆盖返回 `COVERED_BY_OTHER_RECALL`，
  本召回解除但实物不恢复）；FAIL/未复检保持隔离/冻结；同一 (召回,复检单) 重复解除返回首次结果；
  全部实质处置解除后召回结案 `RELEASED`，支持分批复检、逐步部分恢复。
- **重启恢复**：证书版本、召回范围与处置明细、归档标记、冻结原因、复检结论与解除裁决全部
  事务化持久化于 SQLite；`POST /api/admin/reopen` 后完整恢复，未完成复检可继续处理。
- 检定与召回页面（`/metro`）展示**证书沿革、适用范围、受影响任务、器具处置和每次裁决依据**，
  可一键操作八幕：证书换版、临近到期/电压不符拒绝、批次召回（四处置同一事务）、
  召回与许可冲突、重复召回、现场使用中冻结、复检部分恢复、重启后继续处理。

## 雷暴撤离与复工闸门（storm.py）

气象告警命中作业区域时，值班长发布撤离令（`POST /api/tickets/{tid}/storm/evacuation-orders`），
系统在**同一事务内立即固定**本次撤离快照（表 `storm_*`）：人员名册（含每人独立签到口令）、
**仍带电的风险点**（隔离前工作区带电设备；边界开关电源侧防误合反送；带电接地点）、
**现场工器具占有情况**（在库锁定/已领用在现场/随箱持有，逐件快照）与**各安全票所处阶段**，
票据立即冻结，撤离中任何作业（含恢复步骤）、许可与收工一律阻断（`EVACUATION_GATE_CLOSED`）。

- **移动端扫码到达**（`POST /api/storm/batches/{bid}/checkins`）：成员凭**本人名册口令**
  扫避险点码（QR-SH-A/B/C）。代签（口令不符 `PROXY_SIGN_REJECTED`）、同人同点重复扫码
  （`DUPLICATE`，回首次结果不多写）、**已离场人员误入名册**（撤离前已登记 `LEFT`，
  `PERSON_ALREADY_LEFT`）、**未登记人员签到**（`PERSON_NOT_IN_ROSTER`）都给出确定裁决落库；
  同一人更换避险点时旧去向置 `SUPERSEDED`，部分唯一索引保证每人至多一条 `CURRENT` 最新去向。
- **风险点监护**：值班长按风险点指派监护人，监护人凭本人口令确认落实（代确认 `GUARDIAN_PROXY_REJECTED`）。
- **工器具现场去向**（`/tool-sightings`）：在库锁定件无需申报（`TOOL_NOT_ON_SITE`）；
  同件两人各报持有→先到为准后者 `CONFLICT`；持有人改报去向旧行 `SUPERSEDED`；同去向重放 `DUPLICATE`；
  报去向不明（LOST）不是占有主张，任何人之后报找回均可覆盖，不判冲突。
- **复工三条件**：任何人未确认安全（`PERSON_NOT_SAFE`）、关键器具去向不明（`TOOL_LOCATION_UNKNOWN`）、
  风险点未落实监护（`RISK_NOT_GUARDED`），现场负责人清点确认一律拒绝并列出具体未清项。
- **双角色放行（同一撤离批次 + 同一环境版本）**：现场负责人确认人员与器具清点
  （`/confirms/field`），调度员核验**气象解除、网络拓扑版本、隔离边界**（`/confirms/dispatch`，
  告警未消 `WEATHER_ALERT_ACTIVE`、拓扑变化 `BOUNDARY_VERSION_CHANGED`）。环境版本由
  （拓扑版本, 气象序号, 告警序号）三元组摘要构成；任一依据变化（新告警/气象解除/拓扑变更）
  旧确认置 `SUPERSEDED` 保留可查、不删除，须按新版本重新确认；两确认环境不一致闸门不开。
  双确认同环境齐全 → 批次 `WAITING_RESUME` 票据解冻，`/resume` 正式复工。
- **新告警抢占**（`/api/storm/weather-alerts`）：命中区域的**待复工批次**被抢占为 `PREEMPTED`
  （确认全失效、票据再冻结），需值班长就新告警开新一轮撤离批次；撤离中的批次保持 ACTIVE，
  已复工/终局批次不回退。撤离与签到事实永不删除。
- **并发与终局唯一**：撤离令、收工、票据撤销、换班、新告警在 `db.lock` 串行事务内裁决；
  票据已撤销/关闭时撤离令拒绝（`TICKET_NOT_ACTIVE`），开放批次随收工/撤销 `TERMINATED`，
  每角色有效确认、每人当前去向均有数据库部分唯一索引兜底，只有一个最终阶段。
- **幂等**：撤离令/签到/监护确认/去向申报/双确认/复工/告警均支持幂等键或自然键
  （确认键含环境摘要），相同请求重放返回最初结果，绝不多写签到、清点或放行记录。
- **重启恢复**：全部状态事务化持久化于 SQLite，`POST /api/admin/reopen` 后名册快照、
  避险点分布、未清人员/风险/器具、有效/失效确认与批次阶段完整还原，流程可继续。
- 调度端 `/storm` 展示区域态势、告警、撤离批次、人员分布、未清风险与复工依据、裁决流水；
  移动端 `/storm-mobile` 可签到、纠正去向、申报器具去向、本人监护确认并查看每条拒绝原因；
  `POST /api/demo/storm/prepare` 一键准备「已隔离许可+工具领用+名册」的演示现场。



分析员选取安全票的一段审计序号（`POST /api/tickets/{tid}/replays`，`from_seq`~`to_seq`），
系统从事件记录重建该时点的**票据阶段、设备控制权与现场证据**，并逐条显示事件前后状态
（下界之前的事件折叠为基线投影，窗口内逐条展示）。

- **来源固定**：回放创建即固定**事件上界**（`to_seq` 不得超过当前审计序列最大值）与
  **来源摘要**（对窗口内全部事件逐条取 SHA256 摘要再整体取摘要）；之后新增事件序号必然
  越过上界，**改变不了既有回放**。窗口内非本票据事件仅作来源固定、不参与重建。
- **停止规则**：序号缺口、摘要校验失败（`POST /api/replays/{rid}/reverify` 按固定摘要
  逐条复核当前审计库）、事件载荷无法应用（JSON 损坏/缺字段/未知类型），回放都**停在最后
  一个有效事件**并指出具体位置（`halt.position`），绝不跳过错误拼出看似完整的状态。
- **假设分支**（`POST /api/replays/{rid}/branches`）：从任一**有效事件**创建隔离分支，
  试算一项**撤销**（`UNDO_EVENT`）或**设备状态变更**（`DEVICE_STATE`，在基点处生效），
  输出对后续控制权与工序状态的差异及工作区复电安全评估；分支只读正式事件，**不写回正式
  票据、不追加正式审计事件**。多人同时编辑同一分支以 `version` 做乐观并发校验
  （条件更新），冲突提交返回 409，**已保存的假设不被覆盖**。
- **重启恢复**：回放游标（时间线/停止位置）、假设分支与试算、校验失败位置全部事务化
  持久化于 SQLite，进程重启后完整恢复。
- **事故分析报告**（`POST /api/replays/{rid}/reports`）：保留**固定来源摘要、事件范围
  与分支差异**；携带幂等键重复生成返回首次结果，`POST /api/reports/{id}/regenerate`
  重复生成返回同一结果（内容确定性、附完整性自检）。
- 回放页（`/replay`）与报告页（`/report`）可一键演示六条路径：正常重建、缺号停止、
  摘要错误拒绝、假设分支隔离、并发编辑冲突、重启恢复（篡改模拟走
  `POST /api/demo/tamper`，仅用于取证演示）。


## 审计资料外发凭证柜

分析员从一次**已完成（OK）的归约结果**中选取连续审计序号（`POST /api/replays/{rid}/vouchers`），
系统在封存时刻把只读快照**整体固化入库**：封存摘要、**状态截面**（窗口末条事件后的票据阶段/控制权/
现场证据投影）与**逐条事件前后记录**；接收人只能查阅，不能改写正式数据（凭证接口只读本库快照，
不回放正式事件、不写回票据）。

- **封存即固定，截面不被污染**：快照内容在创建时深拷贝于 `vouchers.snapshot`，之后正式审计库
  追加的新记录序号必然越过凭证上界，对正式库的取证篡改也同样**不影响已发出的截面**；
  序号段必须是归约窗口内全部已成功应用的本票据事件，停止（HALTED）的归约不能外发。
- **创建与再次索取幂等**：携带同一幂等键、或“同归约+同连续序号段+同接收人集合”重复封存，
  一律返回**首次凭证的同一份内容**（封存摘要一致），同一凭证不可能出现两份内容。
- **截止时刻与主动作废**：凭证带 `deadline`（懒扫描超时）与作废标记；超时（`EXPIRED`）或主动作废
  （`POST /api/vouchers/{id}/void`）后领取与查阅都返回**确定原因**；作废只停查阅，
  **快照封存保留可审计**，不抹除。
- **并发首次领取只有一人成功**：`POST /api/vouchers/{id}/claim` 以 `(凭证,接收人)` 领取记号 +
  部分唯一索引（一张凭证至多一条 `WON`）做数据库级原子抢占；中签者得查阅权，负方收到带中签者的
  确定失败原因且其 `LOST` 记号同样落库；中签者/负方重复请求均幂等返回本人首次结果。
- **重启恢复**：凭证阶段、领取记号（WON/LOST）、超时与作废结果全部事务化持久化于 SQLite，
  进程重启后完整恢复、流程可继续（`POST /api/admin/reopen` 在线模拟主站重启并补做超时扫描）。
- 外发页面（`/voucher`）展示**凭证阶段、封存摘要、序号范围、领取人和失效原因**，并可一键演示
  七条路径：正常查阅、超时拒绝、主动作废、并发领取、重复请求、追加记录不改快照、重启恢复。


## 值守班组换班接续

调度席为正在执行的工作票开具**交班单**（`POST /api/tickets/{tid}/handovers`），指定**切换水位**
（数据时标阈值）、**移交方**（须为当前持权班组）、**候选承接班组**（可多个，争抢签收）与
**签收期限**。票据的 `write_owner` 记录当前持权班组，**任何时刻一张工作票只允许一个班组
追加现场证据**。

- **原子签收**（`POST /api/handovers/{hid}/sign`）：签收前写权仍归移交方；签收在同一事务内
  以条件更新 CAS 交班单（`PENDING → SIGNED`）并改写票据写权班组，**原子转移给承接方**。
  两个候选班组并发签收只有一方生效，负方收到确定失败原因；重复签收幂等返回首次结果。
- **按水位划分归属**：证据携带数据时标，与切换水位比较——
  - 移交方：水位线内（含签收后到达的**合法迟到内容**）仍入账并标记 `late`；**越线写入拒收**；
  - 承接方：签收前首批数据**挂起**（写权未转移），签收后自动唤醒；首条内容必须声明
    **接续基点**（旧链链头序号），**接不上旧链只能挂起**，以同 `client_id` 修正基点重传后入账；
    回填旧历元（时标未越水位）拒收；
  - 非交班双方班组一律拒收。
- **证据链**：入账内容由服务端定序入链（`seq` 连续、`prev_hash` 指向前条摘要），
  承接方首条接续成功即 `COMPLETED`（接续完成）。
- **关闭触发器**：工作票锁定、边界重算（拓扑变更）、计划取消（撤回）、票据关闭、
  签收超时都会**关闭尚未完成的换班**（待签收/已签收待接续）；只关闭交班单与未决证据，
  **既成设备动作、控制权锁与已入账证据绝不回退**，已转移的写权也不回退。
- **进程恢复**：交班单、写权归属、证据链、挂起内容全部事务化持久化于 SQLite，
  重启后与故障前完全一致，换班可继续推进（`POST /api/admin/reopen` 可在线模拟主站重启）。
- 换班接续台（`/shift`）的调度席与作业设备台实时显示**当前班组、切换水位、交班单阶段、
  双方数据进度与每条内容的处理原因**，并可一键演示：签收前移交方续送、签收后承接方续作、
  移交方越线写入、两班组争抢签收、调度撤单、锁定期间签收失败、进程恢复后继续换班、
  交班单超时关闭。


## 无网作业授权包

调控人员可把一张检修许可单中的**连续指令段**连同**电网版本、执行者、监护者、截止时间**一次性下发
（`POST /api/tickets/{tid}/offline-packages`，授权范围取 SHA256 摘要 `scope_hash`）。

- **断网本地证据链**：移动终端对授权段内每步固定生成四拍证据——扫码 `SCAN`、设备实况 `LIVE`、
  执行确认 `EXEC`、监护确认 `GUARD`；每条记录以前一条摘要为父节点（`prev_hash`，首条为 `GENESIS`），
  摘要对规范化载荷（剔除空值、键排序）拼接父摘要取 SHA256 前 16 位，断网完全本地生成、无需访问主站。
  物理操作由终端就地闭锁：必须持有效授权包、命中段内步骤且前序已证实，越序操作被闭锁拒绝。
- **整包事务裁决**（`POST /api/offline-packages/{pid}/submit`）：网络恢复后服务端一次性核验
  授权范围（票据状态/电网版本/成员/截止时间）与证据链（父子摘要、类型顺序、扫码目标、现场实况与
  主站遥测交叉复核、双人监护），**只让唯一合法序列推进工序**。
  - 记录四态：`PENDING` 未上传、`WAITING` 已上传但待补前序、`ACCEPTED` 已采纳、`REJECTED` 已驳回
    （另有 `DUP_CONFLICT` 同序号内容冲突）。
  - **缺口**：父节点未上传时后续记录只能 WAITING，禁止跨越；后到的前序补传后整包重放即唤醒暂存片段。
  - **幂等**：同一包反复发送不产生第二次状态变化；同序号内容一致返回首次裁决，冲突则先到为准、后到驳回。
  - **链断裂级联**：任一条被终局驳回（篡改/越序/成员替换/实况不符/超时），后续记录级联驳回，绝不跳过。
  - **在线与无网竞争**：先提交者胜，负方记录带可追溯原因（引用先到的在线审计事件序号）驳回，
    但不阻断后续物理序列；整段全被在线抢先完成时授权包为 `SUPERSEDED`，包有贡献则仍为 `COMPLETED`。
- **失效即作废，证据不抹除**：许可单撤销、边界版本改变（拓扑变更）、重新定界、授权超时、
  成员替换、设备实况不符等发生后，旧片段按影响范围拒收（`VOID`/`EXPIRED`）；
  **已证实的物理动作、设备占用（控制权锁）与审计序列永不抹除**。撤销许可后现场残留的开关/接地
  继续锁定设备，恢复到位前禁止重叠开票。
- **重启恢复**：授权包、证据链、同步游标全部持久化于 SQLite，进程重启后未决同步可继续补传推进。
- 调度端与现场端均展示**授权范围、链路连续性、同步游标与逐记录裁决详情**；
  调度端可复现缺口补齐续传、整包重放、在线/无网竞争、失效后补传、重新定界作废、撤销许可残留锁定等结果。

## 核心设计

### 安全边界推导（domain.py）
从工作区向外扩展：线路/母线自由穿过，遇开关即为**边界开关**（必须断开，按离电源距离排序，
先负荷侧后电源侧）；每个边界开关工作侧装设**接地线**；边界开关（禁止合闸）与接地线
（禁止拆除）构成**禁止操作边界**。工作区与电源间无开关则判定无法隔离。

### 票据状态机
`ISOLATING → PERMITTED → RESTORING → CLOSED`，任意阶段可 `WITHDRAWN`；冻结（frozen）为叠加标志。

- **双人复核**：每步须现场回报（扫描设备号 + 遥测核对）后由**不同人员**复核；未真实操作设备
  就回报会被遥测校验拒绝——**不能伪造物理步骤**。
- **许可开工**：全部隔离步骤复核完成且工作区无电才允许。
- **收工送电**：恢复步骤 = 隔离步骤的严格逆序（先拆接地、后合开关），服务端强制按序执行。
- **冻结**：拓扑版本变化、已隔离开关变位、接地线缺失、系统标示牌被摘除、工作区复电、
  接地点带电 → 立即冻结，禁止一切新增操作；已完成的物理步骤原样保留。恢复性操作与
  恢复阶段步骤仍允许执行。拓扑变更后可**重新基线**：按当前拓扑重推边界，已复核且仍有效的
  物理步骤自动保留。
- **撤回**：审计保留；无物理改动的设备控制权立即释放，仍有物理状态（已断开关/已装接地）
  的设备继续锁定，现场恢复后由 `purge-control` 清理。

### 控制权唯一与审计
- `control` 表以设备为主键，数据库层面保证两张票据不能同时控制同一设备；重叠开票返回 409。
- 受控设备在模拟接口上被**闭锁**：仅持票票据按当前步骤解锁操作；`force` 模拟误操作并触发冻结。
- 全部变更写入追加式 `events` 表（全局自增序号），任何状态变化可追溯。
- **幂等**：回报/复核携带幂等键，重复提交返回首次结果并记录 `DUPLICATE_IGNORED`。
- **离线回报**：现场端缓存操作，恢复后 `/sync` 按客户端序号排序、幂等重放。
- **主站重启**：全部状态存于 SQLite，重启后票据、步骤、控制权、审计序号完整恢复。

### 模拟设备接口（/sim）
- `POST /sim/switch` 分/合开关（带闭锁校验、带接地合闸防护）
- `POST /sim/ground` 装/拆接地线（带电挂接地线防护）
- `POST /sim/tag` 挂/摘标示牌（系统牌受票据保护）
- `POST /sim/topology` 增/删连线（拓扑版本递增，触发边界重校验）
- `GET /sim/state`、`GET /api/devices/{id}`（现场扫码查询）

带电状态由电源可达性实时推算（穿过闭合开关），接地、闭锁、标示牌均参与安全校验。
